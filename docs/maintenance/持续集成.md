# 持续集成

主分支更新和拉取请求各运行一个 Windows x64 任务，限时 10 分钟。流程定义在 `.github/workflows/ci.yml`。

## 检查内容

1. 检查 Markdown 本地链接。
2. 编译 WinUI。项目构建会检查预览器的 TypeScript 类型，并构建网页预览器和内嵌 RMP 编辑器。
3. 执行引擎自检，再用 `tests/test_engine.py` 验证城市读取、错误输入、地图与公交 PNG、离线 HTML、引擎握手和关闭。结果直接显示在 Actions 日志中。

手动运行 **Actions → CI → Run workflow** 时，勾选 `full_tests` 可运行完整 pytest 回归，限时 60 分钟。Windows 打包流程也会执行完整回归。

## 本地运行

在 Windows 仓库根目录使用 Python 3.13、Node.js 24 和 `global.json` 指定的 .NET SDK 执行：

```powershell
python -m pip install -r dev/CSLModernMapRenderer/requirements-build.txt
python tools/ci/check_docs.py
dotnet build dev/CSLModernMapRenderer/winui/CSLModernMapWinUI.csproj -c Release
python dev/CSLModernMapRenderer/main.py self-check --report artifacts/self-check.json
python -m pytest -q tests/test_engine.py
```

WinUI 编译方法见[构建说明](../构建说明.md)。

## 测试样本与结果

集成检查使用 `tests/fixtures/` 中的手工样本，涵盖普通与 gzip 城市文件、早期格式、中文路径、关键数据校验、PNG 和 HTML 输出，以及引擎握手与关闭。

本地完整回归使用 `python tools/ci/run_tests.py`，日志写入 `artifacts/tests.txt`。Chromium/WebGL 和 RMP 浏览器检查仍需显式启用。

PNG 会被实际打开并检查尺寸和内容，HTML 会检查页面内容及外部脚本、样式引用。检查城市文件的摘要用于确认 CLI 输出过程保持输入文件原样。

## 人工验收

CI 检查读取、导出和构建是否正常。桌面窗口交互、真实游戏导出、大型城市、复杂立交、站点布局和最终安装包仍按[发行准备](发行准备.md)中的场景验收。

## 流程设置

日常 CI 使用只读仓库权限。Windows 打包流程单独提供手动入口，生成可供验收的文件。发行和 Wiki 同步在审阅后进行。

Actions 固定到已核对的提交，版本注释写在配置中。升级时一并检查版本说明和流程结果。
