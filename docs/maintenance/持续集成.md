# 持续集成

CI 在主分支更新、拉取请求和手动运行时执行。流程定义在 `.github/workflows/ci.yml`。

## 检查内容

| 检查 | 内容 | 运行环境 |
| --- | --- | --- |
| Python 语法 | 检查引擎、工具和测试文件 | Ubuntu、Windows |
| 文档链接 | 检查本地 Markdown 文件链接是否指向现有文件 | Ubuntu、Windows |
| 网页预览 | 按锁文件安装依赖，检查类型并构建资源 | Ubuntu、Windows |
| 引擎自检 | 导入核心模块并检查运行资源 | Ubuntu、Windows |
| 集成检查 | 城市读取、压缩文件、导出和基本通信 | Ubuntu、Windows |
| WinUI 构建 | 编译 Windows 界面及内嵌 RMP 编辑器 | Windows |

引擎使用 Python 3.13，前端使用 Node.js 24，WinUI 使用 `global.json` 中指定的 .NET SDK。Ubuntu 用于检查共用引擎；正式桌面包的目标平台仍是 Windows x64。

## 本地运行

在仓库根目录执行：

```powershell
python -m pip install -r dev/CSLModernMapRenderer/requirements-build.txt
python tools/renderer/build_preview_viewer.py
python tools/ci/check_docs.py
python dev/CSLModernMapRenderer/main.py self-check --report artifacts/self-check.json
python tools/ci/run_tests.py
```

WinUI 编译方法见[构建说明](../构建说明.md)。

## 测试样本与结果

集成检查使用 `tests/fixtures/` 中的手工样本，涵盖普通与 gzip 城市文件、早期格式、中文路径、关键数据校验、PNG 和 HTML 输出，以及引擎握手与关闭。

PNG 会被实际打开并检查尺寸和内容，HTML 会检查页面内容及外部脚本、样式引用。检查城市文件的摘要用于确认 CLI 输出过程保持输入文件原样。

CI 保存自检报告与测试日志，保留 14 天。检查失败时，先看失败的步骤和日志，再按相同命令在本地复现。

## 人工验收

CI 检查读取、导出和构建是否正常。桌面窗口交互、真实游戏导出、大型城市、复杂立交、站点布局和最终安装包仍按[发行准备](发行准备.md)中的场景验收。

## 流程设置

日常 CI 使用只读仓库权限。Windows 打包流程单独提供手动入口，生成可供验收的文件。发行和 Wiki 同步在审阅后进行。

Actions 固定到已核对的提交，版本注释写在配置中。升级时一并检查版本说明和流程结果。
